
# gtm-business

RunnerKit has essentially no market presence yet. As of 2026-09-25 the public repo has 0 stars and 0 forks. Its latest release (v1.3.3, 2026-05-19) has 2 asset downloads in total, nothing has been pushed since May 19, and the repo has no LICENSE file. That last gap matters most for go-to-market: without an OSI license, RunnerKit is legally not open source, so it cannot use the usual channels for this category (awesome lists, homebrew-core, Hetzner Community tutorials, the GitHub Secure Open Source Fund). The market has also shifted against a pitch built only on cost. GitHub cut hosted-runner prices by up to 39% on 2026-01-01 (Linux 2-core is now $0.006/min, and paid plans include 2,000-3,000 minutes). It then postponed, but did not cancel, a $0.002/min platform charge on self-hosted runners. Managed low-cost runners like Ubicloud ($0.00125/min for 2 vCPU, $2.50/month free credit) set a very low price floor, so a solo developer saves only single-digit to low double-digit dollars a month by self-hosting. Similar "self-host made easy" tools earned money in three repeatable ways. Coolify ($5/month for 2 servers, +$3/server) and Dokploy ($4.50/server/month) charge a small monthly fee per connected server for a hosted control plane over servers the user brings, plus sponsorships from infrastructure providers such as Hetzner, Hostinger, Ubicloud and Blacksmith. RunsOn sells a flat commercial license for business use (€300/year, free for non-commercial use), with source access through sponsorship. Actuated sells a team-focused semi-managed service (per-server plans since 2026-05-07: $150/month for the first server, $125/month for each additional one). Pure donation models (CapRover, Dokku OpenCollective, personal GitHub Sponsors pages with about 31-32 sponsors) raise little money, and Earthly (12.1k stars) stopped maintenance after shutting down its cloud. For a tiny team, the most plausible paths are: (A) a free OSS CLI grown through Hetzner and other provider partnerships, earning referral and sponsor revenue; (B) a Coolify-style hosted control plane at about $3-5 per host per month, built on the SEED-001 agent that connects out to the service; (C) a RunsOn-style paid license for teams and commercial use once org and autoscaling features exist. All three require first adding a license, getting BYO reliability green, and measuring activation. The name "RunnerKit" is unclaimed on GitHub, npm, PyPI, crates.io, RubyGems and Docker Hub. However, runnerkit.com, runnerkit.dev and runnerkit.app resolve to registered hosts, and no trademark search was possible. Research limits: the session's WebSearch budget was used up, and outbound network access was limited to GitHub domains and package registries. Vendor sites (runs-on.com, actuated.com, ubicloud.com, coolify.io, hetzner.com, Hacker News) were therefore read through their GitHub-hosted sources (website source repos, docs repos, billing config files) or not at all. Show HN launch data could not be checked.

# managed-competitors

As of 2026-09-25, the market for managed and commercial GitHub Actions runners is splitting into two groups. A handful of well-funded players are pulling ahead. Blacksmith raised a $45M Series B at a $550M valuation (announced 2026-08-12) and reports more than 6,000 customers. Namespace raised $23M (2026-03-23) and Depot a $10M Series A (2026-03). All three now pitch themselves as compute for AI coding agents rather than just faster CI. The rest of the market is thinning out: BuildJet shut down on 2026-03-31, saying GitHub had closed the performance gap. Cirrus Labs joined OpenAI; Cirrus CI shut down on 2026-06-01 and Cirrus Runners stopped taking new customers. Shipfox left the runner business to become an 'AI software factory'. GitHub itself cut hosted-runner prices by up to 39% on 2026-01-01 (2-core Linux went from $0.008 to $0.006 per minute) and added arm64 standard runners for private repos and custom images (GA 2026-03-26). It also announced a $0.002/min fee for self-hosted runners, then postponed it indefinitely after backlash; as of August 2026 no new date has been set. Competitors used the proposed fee in their marketing, calling it a 'self-hosted runner tax' or saying the 'control plane is no longer free', to steer people toward managed runners. Most comparison sites in this space are owned by vendors. Standard 2-vCPU Linux compute is now a commodity at roughly $0.002–0.006/min, and managed runners for GitHub organizations are very crowded. So is the 'runners in your own AWS account' approach (RunsOn, Sprinters, WarpBuild BYOC, Cirun). Several groups are poorly served: solo developers with repos on personal accounts (Blacksmith and GitHub larger runners require an organization; Depot connects at the organization level; GitHub only lets you register a runner to one repo at a time), homelab and own-hardware users, people who want a cheap EU/Hetzner box they manage themselves, air-gapped or GitHub Enterprise Server setups, and odd hardware such as GPUs or Mac minis. Two 2026 changes hit RunnerKit directly. First, Hetzner raised prices three times, and RunnerKit's default server type cpx22 went from €7.99 to €19.49 per month on 2026-06-15. Second, GitHub is now enforcing a minimum self-hosted runner version (a registration minimum of 2.329.0, and each new release must be installed within 30 days); enforcement for GitHub Enterprise Cloud starts today, 2026-09-25. RunnerKit pins runner 2.334.0, while the latest release is 2.337.0. One caveat on sources: nearly all vendor websites were blocked by the network proxy. Figures from pages hosted on github.com were checked against the original source; the rest come from search-engine summaries and are marked medium or low confidence.

## Implications
- Stop leading with 'cheaper than GitHub-hosted' for low-volume solo developers. Lead with 'your own always-warm box': persistent Docker and dependency caches, more RAM and CPU than GitHub's 2-core runner, unlimited minutes and concurrency, hardware you already own, and code that never touches a third-party vendor. Add a `runnerkit cost` or `doctor --cost` command that reads the repo's actual Action
- Change the Hetzner default away from cpx22 (now €19.49/mo for new orders) to cx23/cx33, or cax11/cax21 for arm64 (roughly €5.49–10.49). Show the live monthly price in the plan before any mutation (the hcloud API exposes pricing), and warn that rescaling an existing server moves it to the new price.
- Make personal-account and multi-repo solo use the headline use case: 'one box, all your personal repos'. Add bulk and auto registration (e.g., register every repo you own, or new repos as they appear) and document it against GitHub's rule that a runner registers to only one repo at a time.
- Treat GitHub's runner version enforcement as a top reliability concern. Bump the pinned runner (2.334.0 → current 2.337.x) automatically in releases or resolve it at bootstrap, add a doctor finding that compares the installed runner version with the latest release and the 30-day window and checks registration minimum 2.329.0, and have `recover` / `upgrade-runner` fix it.
- Don't compete in the managed 'fast runners for teams' segment. Build ephemeral autoscaling on Hetzner (and optionally BYO hosts) on GitHub's actions/scaleset client, without a SaaS control plane, as an open-source, CLI-driven alternative to Cirun-on-Hetzner and RunsOn-for-Hetzner.
- Market to EU and sovereignty users: 'runs on your Hetzner or EU box, no third-party control plane, code never leaves your machine'. Consider a cheap per-job provenance or SBOM record (e.g., syft output stored on the host) as an optional feature.
- Use the vendor exits in messaging ('your CI shouldn't depend on a startup's runway'), and consider macOS on the user's own Mac mini as a later extension using now-permissively licensed Tart.
- Document and test routing agent workloads to RunnerKit runners where GitHub allows it (the Copilot code review runner setting; ephemeral mode for the coding agent, including the firewall caveat), and be clear where ARC is the only officially supported route.
- Make every cost comparison robust to a future self-hosted fee (show results with and without a $0.002/min charge) and note that public repos and GHES were exempt. Air-gapped and GHES support could become a differentiator.
- Distribution: get RunnerKit listed in the maintained runner lists (e.g., jonico/awesome-runners, where CRACI recently submitted a PR, and neysofu/awesome-github-actions-runners, which is stale and still lists BuildJet), and publish neutral break-even and 'Hetzner after the 2026 price hikes' guides aimed at homelab, Hetzner and personal-repo search terms.

# oss-selfhosted-tools

The open-source and self-managed GitHub Actions runner tooling changed a lot in 2026. The biggest change: on 2026-02-05 GitHub released the actions/scaleset Go client in public preview (MIT license, v0.4.0 on 2026-05-05, commits through 2026-09-16). It lets anyone build a scale-set autoscaler without Kubernetes, supports repo-level scale sets and PAT auth, and ARC 0.14.0 (2026-03-19) now runs on it. Around it the ecosystem has settled on ephemeral runners with JIT registration, driven by a controller that dials out. The main tools are ARC (6.5k stars, very active, Kubernetes required, legacy persistent mode deprecated), terraform-aws-github-runner (3.1k stars, v7.11.0 on 2026-08-17, AWS plus Terraform), RunsOn (1.3k stars, AWS-only, from €300/yr commercial license), GARM (407 stars, 10+ providers, a server to run), and a small Hetzner group: Cyclenerd hcloud-github-runner (182 stars, runs inside the workflow, one VM per job) and TestFlows Hetzner runners (101 stars, an always-on autoscaler used for Altinity ClickHouse builds). The closest new rival is Zoomies (eyupio/zoomies). v1.0.0 shipped 2026-09-13 and it has 51 stars. It has the same "single Go binary, no Kubernetes, one-line installer" pitch as RunnerKit, but runs only ephemeral jobs in containers, uses outbound-only agents, has a web UI, and has no cloud provisioning. The basic config.sh/svc.sh flow still has real pain points: 1-hour registration tokens, runners auto-removed after 14 days offline, a rule to update within 30 days, and minimum-version enforcement (v2.329.0) whose GHEC full-enforcement date is today (2026-09-25). No personal-account-level runner sharing exists. The economics have moved against light self-hosting (my inference from the price data): GitHub-hosted Linux 2-core fell to $0.006/min on 2026-01-01, the $0.002/min self-hosted fee is postponed but not cancelled, and secondary sources report two Hetzner price rises in 2026. Inference: RunnerKit still has a defensible niche in "no control plane to run, no K8s/Terraform/AWS/webhook endpoint, a CLI on your laptop that configures a BYO SSH box or one Hetzner VM, persistent warm-cache runners with host diagnostics and image parity." No other open-source tool I found combines these. It is clearly behind on autoscaling and concurrency, JIT/scale-set APIs, org-level registration, per-job isolation on BYO hosts, macOS/Windows, dial-out architecture, and runner-version freshness (it pins 2.334.0 while upstream is at 2.337.0).

# pricing-economics

As of 2026-09-25, GitHub-hosted private-repo minutes are cheap: Linux 2-core is $0.006/min (down from $0.008 on 2026-01-01), ARM 2-core $0.005, the new 1-vCPU ubuntu-slim $0.002, Windows $0.010 and macOS $0.062. Free/Pro accounts get 2,000/3,000 included minutes. Public repos get unlimited free 4-vCPU/16 GB runners. The announced $0.002/min self-hosted "cloud platform charge" (announced 2025-12-16 for 2026-03-01) was postponed within days. GitHub's docs still say Actions is "free for self-hosted runners", and I found no new date. GitHub's own impact data shows only about 2.8% of individual users with private-repo Actions usage pay for overage, so the cost pain RunnerKit's "solo developer" thesis assumes is rare. The supply side moved sharply against RunnerKit's cloud path. Hetzner raised prices on 2026-04-01 and again on 2026-06-15 for new orders. RunnerKit's default cpx22 went from €5.99 to €7.99 to €19.49/month, about 4x the "approx €4.90/month" hardcoded in internal/provider/profile.go. The cheap CX and CAX lines were marked unavailable in early September 2026. At current prices, an always-on CPX22 only beats GitHub-hosted above about 5,800 Linux minutes/month on the Free plan (about 6,800 on Pro). A RAM-equivalent CPX32 breaks even at about 8,900 minutes. Managed runners are cheaper than a persistent Hetzner box until about 8,700 minutes (Blacksmith: $0.004/min with 3,000 free) or about 12,600 minutes (Ubicloud premium: $0.002/min). Ephemeral one-VM-per-job on Hetzner is a poor deal: billing rounds up to whole hours, so every job costs at least one hour, and each VM adds minutes of provisioning. Self-hosting clearly wins in four cases: heavy private-repo CI (roughly >6-9k min/month, typical of small teams more than solo devs), users who need more than 2 cores or 8 GB (break-even against GitHub larger runners is about 2-3.5k min/month), BYO owners of existing hardware (near-zero marginal cost), and workloads that gain from warm local caches, long jobs or private network access. Recommendation: stop leading with "cheaper for solo devs". Lead with BYO, performance and warm caches, and heavy-usage indie teams, and make cost claims live and honest.

Research limits first. The session's WebSearch budget was already used up, and the egress proxy blocked github.blog, docs.github.com, vendor blogs, news sites, codeberg.org and hetzner.com. Findings on EU sovereignty and Hetzner pricing are unverified. (1) AI agents now drive a lot of GitHub activity. A tracker of public GitHub search counts shows agent-authored PRs growing from about 63k (2025-05-26) to about 11.45M (2026-09-25), with about 1.09M new in August 2026 alone. GitHub's own agents run on Actions runners: Copilot cloud agent (the renamed coding agent), Copilot code review, which bills Actions minutes on private repos, and GitHub Agentic Workflows (preview). All of them now document a self-hosted runner path. (2) GitHub pushes agent workloads toward ephemeral, autoscaled runners. For Copilot cloud agent it recommends ephemeral single-use runners via ARC or the new Runner Scale Set Client. For Copilot code review it says ARC is the only supported self-hosted option and warns against non-ARC runners. Copilot cloud agent only supports Ubuntu x64 and Windows runners. That is a direct threat to RunnerKit's persistent systemd model for agent workloads. But GitHub open-sourced the Runner Scale Set Client as a Go module (actions/scaleset) in February 2026, which gives a Go CLI like RunnerKit a direct way to fix this. (3) Agent vendors are also building their own compute outside Actions: GitHub cloud sandboxes (billed per second, preview), Cursor Automations "private workers", E2B and Daytona. So being a GitHub runner does not cover all agent compute. (4) Supply-chain attacks moved into the CI runtime itself. tj-actions (2025) and the Shai-Hulud waves (Sept/Nov 2025, including rogue self-hosted runners as backdoors) were followed in 2026 by: TanStack (pull_request_target plus cache poisoning plus an OIDC token pulled from runner memory), Nx Console, Megalodon (5,561 repos injected with malicious workflows), Miasma (reading Runner.Worker memory), and the August 4 keyv/ChainDrop wave (444 packages carrying valid npm provenance). GitHub responded with a SHA-pinning policy, immutable releases, read-only cache for pull_request_target, and a default policy blocking pull_request_target in public repos, enforced from November 2, 2026. Its guidance says self-hosted runners should "almost never" be used on public repos and can be "persistently compromised". (5) On pricing, the planned $0.002/min fee for self-hosted runners is still postponed; docs as of 2026-09-25 say self-hosted usage is free. Hosted runners got cheaper (Linux 2-core $0.006/min, arm64 $0.005, 1-core slim $0.002), which weakens a pure cost argument. (6) Platform discontent is real but niche. Zig left GitHub for Codeberg (Nov 2025) citing Actions bugs, and Gitea and Forgejo have their own runners. Net: the opportunity is shifting from "cheap persistent runner" toward "secure, agent-ready runners on hardware you own, including ephemeral per-job isolation". An Agent Skill is a cheap way to distribute that; demand for an MCP server is unproven.

# user-voice-demand

Solo developers show real but narrow demand for self-hosted GitHub Actions runners. Most of the complaints come from teams and orgs. GitHub's own data makes the point: under the proposed $0.002/min self-hosted fee (announced 2025-12-16, postponed about a day later), only 0.09% of individual Free/Pro users with private-repo Actions usage would have paid more, with a median increase under $2/month. For most solo developers the included quota (2,000 min, "over 33 hours") is enough. The fee backlash was loud: 263 thumbs-up and 138 comments/replies on the postponement thread, and at least 7 HN submissions. It was about principle ("it's MY machine"), compliance, donated OSS hardware and org-level bills of $140 to $3.5k/month. It did not reveal a large pool of solo developers blocked on cost. Pull toward self-hosting in 2026 comes more from GitHub Actions reliability (99.33% 90-day Actions uptime after the 2026-08-17 outage; 57 Actions outages in 12 months per a third-party tracker), special hardware (Apple Silicon tools Cilicon at 1.2k stars and Tartelet at 797) and slow or underpowered hosted runners. A small, values-driven migration to Codeberg/Forgejo also exists (Zig, bloggers), and those migrants still self-host runners, often on Hetzner. The largest measurable operational pains are in actions/runner issues and community threads: runners that look online but don't pick up jobs (#120813: 103 comments, unanswered; #3609: 92 thumbs-up, 141 comments; "Runner not found" #3857: 116 thumbs-up); forced version deprecation that silently breaks persistent runners (#3767, #4203, #4442, plus the 30-day update rule); disk and Docker rot and root-owned workspace files (#434: 132 thumbs-up, open since 2020); no fallback to hosted runners when the self-hosted runner is offline (#20019: 197 upvotes, and GitHub says it has no plans to build it); and security fears for persistent or public-repo runners, sharpened by the Shai-Hulud worm installing rogue runners in Nov 2025. RunnerKit already covers setup, persistent vs ephemeral safety gating, several repos on one personal-account host, parity with the hosted image, and diagnostics and recovery after the fact. It does not yet cover continuous self-healing and alerts, disk/Docker hygiene, version-drift watching, fallback to hosted runners, parallel runners per repo, or first-class Apple Silicon or Forgejo support. Those are the highest-value gaps. RunnerKit has 0 GitHub stars as of 2026-09-25, so adoption is unproven. Research limitation: Reddit was not reachable by the search tool, and HN, dev.to and most news sites were blocked for fetching. HN point counts and Reddit sentiment could not be measured directly. Verified quotes and counts come mainly from github.com community discussions and actions/runner issues, plus search-engine snippets of news coverage. The web-search budget also ran out partway through, so events after about mid-2026 (for example, whether the fee was ever brought back) could not be re-checked.

## Implications
- Reposition away from 'avoid GitHub's fee' and 'cheaper minutes' toward 'your own box or a €5–40 Hetzner VM as a runner that stays healthy'. Lead with day-2 reliability, not day-1 install.
- Ship a host-side watchdog (a systemd timer run by the runner user) that detects 'online but not taking jobs', lost communication, 'Runner not found' after the 14-day auto-removal, and deprecated runner versions, and then restarts, re-registers or upgrades automatically. Add optional notifications (email, ntfy or webhook), and expose results in doctor --json next_actions.
- Add disk and workspace hygiene: a scheduled docker prune with retention, cleanup of runner-update leftovers (bin.<ver>/externals.<ver>), repair of root-owned workspace files (for example a scoped sudo chown hook, or Docker userns-remap), and a doctor disk-pressure finding.
- Provide a first-party 'fallback to hosted' pattern, such as `runnerkit workflow snippet --fallback` or a small composite action. It would pick the RunnerKit label when that runner is online and idle, and otherwise ubuntu-latest.
- Add concurrency: `--runners N` per repo per host, so matrix builds can run in parallel, and optional org-level registration for developers who keep side projects in an org.
- Make ephemeral on BYO actually clean: a container-per-job or microVM-per-job option on the user's own host. Also add `runnerkit audit`, which lists every runner registered on the user's repos and flags unknown ones.
- Treat Apple Silicon and macOS as a first-class path (launchd service, optionally Tart VMs), and consider GPU hosts later.
- Consider Forgejo/Codeberg runner support (forgejo-runner over the same SSH and systemd bootstrap, plus Hetzner) as a low-cost expansion.
- Keep the solo CLI free and open source. If you monetize, target small teams (managed Hetzner fleets, alerts, shared access) rather than individuals.
- Evaluate actions/scaleset (JIT and scale-set primitives) for Hetzner ephemeral scale-to-zero, instead of one server per `runnerkit up`.
- Invest in distribution now: 0 stars means there is no user feedback loop. Write pain-specific posts ('why your self-hosted runner stops picking up jobs', 'disk full on self-hosted runners') and link RunnerKit from the relevant GitHub community threads where it actually helps.
